# ヒアリング台本（question-bank）

講師から受講者ごとの所見を引き出すための質問集。1問ずつ聞き、回答を hearing_state.json に逐次保存する。講師が詳しく語れる場合は主質問だけで進み、語りが薄い場合にプローブで掘る。

## 聞き方の規範

- 1回の発話で質問は1つ。回答を要約して確認してから次へ進む。
- 講師の発言は「観察された行動」としてそのまま記録する。解釈への変換はこちらが下書きし、講師に確認を取る。
- 講師が語っていない事実（日付・発言・成果物名）を補作しない。語られなかった観点は「所見に挙がっていない」として扱う。
- 否定的な人物評（〜できない人、向いていない）が出たら、根拠となった行動を聞き返し、行動の記述として記録する（writing-style.md の言い換え表を使う）。
- 音声ヒアリング時は言いよどみ・沈黙に割り込まず、話し始めたら譲る。

## フェーズA 前提確認（最初に1回）

| # | 質問 | 記録先 |
|---|---|---|
| A1 | 研修を実施した会社名は？ | case.client |
| A2 | 研修は何日間でしたか？ | case.days |
| A3 | 今回は何人受けましたか？ 受講者の名簿（氏名）をください | people[].name |
| A4 | このレポートの主な用途は？（配置検討／育成計画／本人フィードバック） | 進行の力点調整 |
| A5 | 受講者について事前に知っていた情報はありますか？（開発経験など） | timeline冒頭（事前情報として区別） |

## フェーズB 受講者ごとの質問（名簿順に一人ずつ）

導入: 「では一人ずつ伺います。◯◯さんは、研修全体を通してどうでしたか？」

| # | 主質問 | 狙い | 記録先 |
|---|---|---|---|
| B1 | ◯◯さんの全体的な印象は？ | 自由回答の核 | summary/headline素材 |
| B2 | 特に印象に残った日や場面は？ 序盤の操作まわり・中盤・最終日で違いはありましたか？ | 日別の行動記録 | timeline |
| B3 | 例題やテンプレートを、そのまま使う人でしたか？ 自分なりに変える人でしたか？ | 理解・活用軸 | axis_detail[0].observed |
| B4 | 想定と違う結果が出たとき、どう反応していましたか？ | 理解・活用軸（応用/問題対処） | axis_detail[0] |
| B5 | 自分から動いた場面はありましたか？ 指摘やフィードバックへの反応は？ | 意欲・主体性軸 | axis_detail[1].observed |
| B6 | 作ったものの「その後」（誰が使うか・手順・保守）に触れる発言はありましたか？ | 組織活用軸 | axis_detail[2].observed |
| B7 | もしAI活用のチームに入れるとしたら、リーダー・サブ・実務担当・後から参加のどのあたりが浮かびますか？ その理由は？ | 役回りの直感 | pos / leadership |
| B8 | この人に何かを任せるとき、心配な点はありますか？ | リスク | risks / issues |
| B9 | 実務ではどんなことをやってくれそうですか？ | 活用イメージ | work_image |

### 語りが薄いときのプローブ（B番号に対応）

- B1が「普通でした」で止まる → 「他の受講者と比べて、何か1つ違いを挙げるなら？」「5日目の様子は初日と変わりましたか？」
- B2が出ない → 「操作でつまずいた人はいましたか？その中に◯◯さんは？」「演習の完了は早い方でしたか？」
- B3が曖昧 → 「◯◯さんの成果物は、配布例とほぼ同じでしたか？どこか違いましたか？」
- B4が出ない → 「エラーや変な出力のとき、手が止まる人と自分で直す人がいます。◯◯さんはどちら寄り？」
- B5が出ない → 「質問はしていましたか？質問の中身は具体的でしたか？」
- B6が出ない → 「『これ誰が使うんですか』『あとで手順書いりますね』のような発言はありましたか？」
- B7が決めきれない → 「少なくとも“いきなりリーダー”はあり？なし？」から絞る
- B9が出ない → B3〜B6の回答から候補を3つ提示し、「近いのはどれですか」と選んでもらう

### 深掘りの上限

1人あたり主質問9問＋プローブ数問で15分目安。全フィールドが一次情報で埋まらなくても、schema.md の必須（scores/reasons/timeline/axis_detail/pos/strengths/issues/risks/placement/work_image）が埋まれば次の人へ進む。空欄が残るフィールドは、講師の回答からの導出案を提示して承認を取る。

## フェーズC 採点（提案→承認）

1. 尺度アンカー（design-spec.md 参照、または全体版P2と同文）を提示。
2. 各軸について「ヒアリングの◯◯という行動から、アンカーの△点に当たると考え、□点を提案します」と根拠つきで提示。
3. 講師の承認・修正を受けて確定。内訳合計＝総合点をその場で確認する。
4. 修正で0.5点動かす場合も、対応する行動根拠を講師に一言もらい reasons へ反映する。

## フェーズD 下書き承認

1人分の要約カード（総合点・役回り・強み3・課題3・実務イメージ）をテキストで提示し、承認後に次の受講者へ。全員完了後、全体編（役割の骨格・配置判断のポイント・適性マップ座標）を提案して承認を取る。マップ座標は横軸=作る側⇄使う側、縦軸=伴走前提⇄自走、の定性配置で、講師に位置の感覚を確認する。
