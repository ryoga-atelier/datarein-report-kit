# 文体規範（writing-style）

レポート本文の文体は「である」調の断定＋根拠。以下は本キット固有の規則で、一般規範は ng-palette（禁止フレーズ）、japanese-tech-writing（空句・論証）、bookmark-avoid-ai-writing（AI癖の除去）、cognitive-rhythm-writing（読み物の緩急）を必要時に参照する。

## 三大原則

1. **観察と解釈を行で分ける。** 講師が語った行動は「研修で見られた行動」に、点数や適性への意味づけは「解釈」「含意」に書く。混ぜない。
2. **所見に無い事実を補作しない。** 日付・発言引用・成果物名は講師が語った範囲だけ。語られなかった領域は「研修所見に挙がっていない」「実務で確認する」と書く。
3. **人格を評価しない。** 評価するのは研修で見えた姿勢・理解・行動。低評価者ほど「支援があれば何ができるか」「育成の土台」を必ず書く。排除の断定（〜の対象外）ではなく優先順位（〜を先に置く）で書く。

## 禁止語（生成器の BANNED と同期。ここが規範の説明、機械検査は build/validate）

- テンプレ・曖昧強調: かなり便利／結構／割と／さまざま／ぜひ／いかがでしたでしょうか／〜じゃないかなと思います／ぐんぐん
- LLM空句: 非常に／極めて／多角的に／に他ならない／重要なのは〜である（予告型）
- 木霊口調の混入: じゃ。／じゃが、／ゆえ、／おらん／ぬし／わし／言うて
- 人物への否定語: 足枷／粗悪／置いてきぼり／足を引っ張る／受動的
- 工程の漏れ検知: 次回／未反映／未確認／＊（説明配分は使わない。全点数に行動根拠を付ける）
- 段階番号（第1段階等）と「90日計画」: 参加時期は「〜が明確になってから」等の条件で書く

## 話し言葉→書き言葉の変換表（ヒアリング録からの実例）

| 講師の言い方 | レポートの書き方 |
|---|---|
| ぐんぐん伸びる | 吸収が速く、経験に比例して伸びる |
| 数をこなす | 繰り返しの多い／件数を重ねる |
| 実務投入まで持ち込める | 実務で使い始める段階まで進められる |
| 応用が甘い | 応用的な工夫は見られず、型に沿った作り方にとどまった |
| 盲点 | 視野の外にある |
| 作って終わり | 形になった時点で完了と捉えやすい |
| 足を引っ張る／足枷 | 検討速度と習熟ペースが合わず、進行が滞る。双方の負担が大きい |
| 置いてきぼり | 議論の進行に理解が追いつかない場面があった |
| 受動的 | 働きかけを待つ場面が多かった |
| ついていくので精一杯 | 進行を追うことに集中しており、応用まで至らなかった |
| リーダー向きじゃない | 現時点ではリーダー役より◯◯を先に置く／リーダー役の検討は◯◯の実績の後 |
| 言語化する（空句化しやすい） | 言葉にする／言葉で説明する／言葉に組み立てる |

## 点数と文章の整合

- 各軸の reasons は「講師所見：◯◯。ISSUER判断：△△でx.x点、基準比±y.y点。」の型。
- 尺度アンカーの区分文と矛盾する点数説明を書かない（生成器が「尺度上の位置」を自動表示するため、ズレは読者に見える）。
- 順位づけの創作をしない（「N名の中で最も◯◯」は、講師がそう言った時だけ）。
- 1場面の観察を「一貫している」と拡大しない。場面を特定して書く。

## 執筆後の点検

生成前に本文素材（case.json）へ、生成後に編集用mdへ、validate.py の禁止語検査を通す。区別: 機械検査の通過（machine_ok）と、描画の目視・意味の確認は別物として報告する。
